استضافة PMS على السيرفر (دائمة)
================================

الهدف: التطبيق يعمل دائماً على السيرفر، ويمكن فتحه من أي جهاز على الشبكة،
والقارئة تتصل عبر IP السيرفر.

أ) التثبيت مرة واحدة
-----------------
1) انسخ مجلد Publish\PMS.Server بالكامل إلى السيرفر، مثلاً:
      C:\PMS
2) تأكد أن السيرفر يصل لقاعدة البيانات في appsettings.Production.json
3) افتح PowerShell كمسؤول، ثم:

      cd C:\PMS
      Set-ExecutionPolicy -Scope Process Bypass
      .\install-service.ps1

4) افتح من أي جهاز على الشبكة:
      http://<IP-السيرفر>:5260

5) على القارئة (Cloud / ADMS):
      Server IP = <IP-السيرفر>
      Port      = 5260
      أو URL    = http://<IP-السيرفر>:5260/iclock

ب) ماذا يفعل install-service.ps1 ؟
---------------------------------
- يفتح جدار الحماية للمنفذ 5260
- يثبت خدمة Windows باسم: PMSWebHost
- تشغيل تلقائي مع إقلاع السيرفر
- يبدأ التطبيق فوراً (بدون الحاجة لـ start-pms.cmd)

ج) إدارة الخدمة
---------------
- services.msc  →  ابحث عن "PMS Web Host"
- أو PowerShell:
      Start-Service PMSWebHost
      Stop-Service PMSWebHost
      Restart-Service PMSWebHost

د) إزالة الاستضافة
------------------
      .\uninstall-service.ps1

هـ) تشغيل يدوي مؤقت (بدون خدمة)
-------------------------------
      .\start-pms.cmd

و) الوصول من خارج الشبكة الداخلية (الإنترنت)
--------------------------------------------
هذا يتطلب IP عام أو VPN / Port Forward من الراوتر إلى السيرفر:5260
ولا يُنصح بفتحه مباشرة على الإنترنت والتطبيق حالياً بدون حماية دخول قوية.
للاستخدام الداخلي/الشركة: IP السيرفر على الشبكة كافٍ.

اختبار القارئة
--------------
في شاشة «حالة الأجهزة» يجب أن يظهر IP القارئة في سجل الاتصال (وليس 127.0.0.1).
الشاشة تعرض عناوين ADMS الصحيحة الخاصة بهذا الجهاز — انسخ أحدها إلى القارئة.

عند بدء التشغيل يطبع اللوج:
      Listening on: http://0.0.0.0:5260
      Reader ADMS URL candidate: http://<IP>:5260/iclock

تشخيص متقدم عند عدم وصول القارئة
--------------------------------
في appsettings.Production.json اضبط:
      "ZkTeco": { "LogRawTcp": true }
ثم أعد تشغيل الخدمة وراقب سجل ZkTeco.Tcp:
- ظهور بايتات من IP القارئة  => القارئة تصل فعلاً (المشكلة في البروتوكول/المسار)
- لا شيء من IP القارئة        => الطلب لا يصل للسيرفر (إعداد ADMS أو الشبكة)
